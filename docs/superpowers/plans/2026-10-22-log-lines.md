# Log lines implementation plan

**Goal:** Make `zm2 logs service --lines N` show the last N journal entries, then follow; `--nostream` prints and exits; zero follows only new entries.

**Architecture:** Let a single `journalctl -f -n N` request provide history and live output, avoiding duplicate history and a tail/follow race. Select services from monitor metadata, not obsolete custom log file paths. Preserve CLI defaults (15), programmatic defaults (20), service name/id, namespace and regex selection. Pass the count through JSON and formatted streaming too. Keep unrelated filtering/formatting behavior unchanged.

**Tech stack:** Node.js, Mocha, built-in assert, systemd/journald.
