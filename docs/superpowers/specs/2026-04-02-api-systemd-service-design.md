# ZM2 API as Systemd Service — Design Spec

## Overview

Convert `zm2 api` from a foreground blocking command to a systemd-managed service. The API server runs as `zm2-api.service`, logs go to journald, and subcommands control the lifecycle.

## Decisions

- **Systemd service**: Consistent with how ZM2 manages everything else
- **Not registered in StateStore**: This is infrastructure, not a user app
- **Standalone entry point**: `lib/API/HttpApiServer.js` runs as the ExecStart
- **Default host 127.0.0.1**: Only listens locally unless explicitly overridden

## CLI Commands

| Command | Action |
|---------|--------|
| `zm2 api [--port N] [--host IP]` | Install and start `zm2-api.service` |
| `zm2 api stop` | Stop the service |
| `zm2 api status` | Show running state, port, host, API key |
| `zm2 api restart` | Restart the service |
| `zm2 api remove` | Stop and remove the unit file |

### Options

- `--port <number>` / `ZM2_API_PORT` — Port to listen on (default: 9615)
- `--host <ip>` / `ZM2_API_HOST` — IP address to bind to (default: 127.0.0.1)

Options are baked into the unit file at install time. To change port/host, run `zm2 api remove` then `zm2 api --port X --host Y`.

## Systemd Unit File

Generated by `API.prototype.api()`, installed at `/etc/systemd/system/zm2-api.service`:

```ini
[Unit]
Description=ZM2 API Server
After=network.target

[Service]
Type=simple
ExecStart=/path/to/node /path/to/zm2/lib/API/HttpApiServer.js
Environment=ZM2_HOME=/home/user/.zm2
Environment=ZM2_API_PORT=9615
Environment=ZM2_API_HOST=127.0.0.1
Restart=on-failure
RestartSec=5
TimeoutStopSec=10

[Install]
WantedBy=multi-user.target
```

- `ExecStart` uses absolute paths resolved at install time (via `process.execPath` for node, `__dirname` for the script)
- `ZM2_HOME` set to the installing user's ZM2 home directory
- Port and host passed as environment variables

## New File: `lib/API/HttpApiServer.js`

Standalone entry point executed by systemd. Does:

1. Read `ZM2_HOME`, `ZM2_API_PORT`, `ZM2_API_HOST` from environment
2. Create an `API` instance with `{daemon_mode: false}`
3. Call `Client.start()` to connect to systemd
4. Load API key from `$ZM2_HOME/api-key` via `HttpApi.loadOrCreateApiKey()`
5. Create server via `HttpApi.createServer(api, apiKey)`
6. Listen on `host:port`
7. Log startup message to stdout (journald captures it)
8. Handle SIGTERM for graceful shutdown

This file reuses all existing `HttpApi` functions — no duplication.

## Modified Files

### `lib/API.js`

`API.prototype.api()` becomes an installer/controller instead of a foreground server:

- **No subcommand (default)**: Generate unit file, install via `Systemd.installUnit('zm2-api', content)`, start via `Systemd.start('zm2-api')`, print API key and exit.
- **`stop`**: `Systemd.stop('zm2-api')`
- **`restart`**: `Systemd.restart('zm2-api')`
- **`remove`**: `Systemd.removeUnit('zm2-api')` (this stops, disables, and deletes)
- **`status`**: `Systemd.getStatus('zm2-api')` + print state, port, host, API key

### `lib/binaries/CLI.js`

Update the `zm2 api` command to accept subcommands and `--host`:

```
zm2 api [start] [--port N] [--host IP]   # start is implicit default
zm2 api stop
zm2 api status
zm2 api restart
zm2 api remove
```

The first positional argument is the subcommand. If it's not one of stop/status/restart/remove, it's treated as `start`.

### `lib/API/HttpApi.js`

Update `createServer` to accept `host` parameter so it can bind to a specific address. Currently hardcoded to `0.0.0.0` — needs to be configurable.

## API Key

Same mechanism as before:
- Stored at `~/.zm2/api-key`
- Generated on first `zm2 api` if it doesn't exist
- Printed to terminal when running `zm2 api` or `zm2 api status`
- The systemd service reads it from the same path at runtime

## Logs

```bash
zm2 api status              # Quick status check
journalctl -u zm2-api -f    # Stream logs
journalctl -u zm2-api -n 50 # Last 50 lines
```

## Error Handling

- `zm2 api` when already running: Print message "ZM2 API already running" and show current status. Don't reinstall.
- `zm2 api stop` when not running: Print "ZM2 API is not running", exit cleanly.
- `zm2 api` without systemd: Print error and exit (same as other ZM2 commands).
- `zm2 api` without root: Print error — installing systemd units requires root.

## Testing

Unit tests in `test/programmatic/http_api.mocha.js`:

- Unit file generation: verify correct format with port/host/paths
- Subcommand parsing in CLI
- HttpApiServer entry point logic (mock API, verify it reads env vars and starts server)

No E2E tests (requires systemd + root).

## Migration from Current Implementation

The current foreground `api()` method and `zm2 api` command are replaced. The `HttpApi.createServer()` function stays unchanged — it's reused by the new `HttpApiServer.js` entry point.
